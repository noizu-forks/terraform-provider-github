# Layout — `github/`

The provider package: everything Terraform sees. Single Go package `github`.

```text
github/
├── provider.go                 # provider schema, Configure/ConfigureProvider (auth chain), ResourcesMap (88), DataSourcesMap (75)
├── config.go                   # Config + Owner structs, RateLimitedHTTPClient, REST/GraphQL client builders, base-URL/GHES parsing
├── transport.go                # etagTransport, RateLimitTransport, RetryTransport, preview-header injector
├── noizu_provider.go           # Noizu extension layer: noizuResources/noizuDataSources maps, registerNoizuExtensions, mergeNoizuMaps
├── noizu_provider_test.go      # extension-layer unit tests (collision panic, empty maps)
│
├── resource_github_*.go        # 106 implementation files (88 registered names; deprecated/consolidated files remain)
├── resource_github_*_migration.go  # 18 StateUpgrader/migration files
├── data_source_github_*.go     # 75 data-source implementations
├── util*.go                    # 15 utility files (see below)
├── acc_test.go                 # acceptance-test harness: providerFactories, TF_ACC gating, mode skips
├── acc_helpers_test.go         # shared acceptance helpers
├── provider_test.go, config_test.go, transport_test.go, apps_test.go, helpers_test.go, migration_test.go
└── test-fixtures/              # deploy-key fixtures (gitignored keys are generated by tests)
```

Test files are interleaved with implementations (`*_test.go` alongside), per upstream convention documented in `ARCHITECTURE.md`.

## Utility files (`util*.go`)

| File group | Contents |
|---|---|
| `util.go` | `buildID` / `parseID2..4` / `escapeIDPart` / `buildChecksumID`, validators, string expand/flatten |
| `util_team.go`, `util_v4_repository.go` | team ID/slug and repository node-ID resolution |
| `util_permissions.go` | permission name normalization (`read`↔`pull`, `write`↔`push`) |
| `util_diff.go` | `CustomizeDiff` funcs (repository, secret, team, secret-variable visibility) |
| other `util_*.go` | domain helpers (rules, labels, and similar) grouped by API area |

## Naming contract

| Component | Pattern |
|---|---|
| Resource constructor | `resourceGithub<Entity>` |
| Data source constructor | `dataSourceGithub<Entity>` |
| CRUD | `resourceGithub<Entity><Op>` (context-aware) |
| Migration | `resourceGithub<Entity>InstanceStateUpgradeV<N>` + `...ResourceV<N>` |
| Test | `TestAccGithub<Entity>` with `t.Run` subtests |
| Noizu additions | `github/noizu_resource_<thing>.go`, names `github_noizu_<thing>` |

## Notes

- Package is `github` (matching upstream); Noizu code lives in `noizu_*.go` in the same package to reach `Config`/`Owner`/`ghclient` without import cycles.
- `github/` also has a `test-fixtures/` directory; keys there are generated, not committed.
